## 1. Architecture

OKF-Token Forge is a standalone, deterministic repository indexer. The CLI and DSH tools share a compiler that walks selected files, extracts structural metadata and local dependencies, and writes an OKF-shaped Markdown bundle plus incremental state under `.okf/`. Queries refresh that bundle, rank concepts, and return a character-capped slice. There are no model calls.

Its separation from Decision Forge and Skillforge is sound and should remain intact.

**Trust boundary:** repository contents, filenames, manifests, and any pre-existing `.okf/` files are untrusted inputs. The compiler has filesystem write authority; the query tool moves repository-derived content into model context. `.state.json` is a cache, not evidence that generated content is authentic or current. The caller-selected `root` is also a filesystem authority boundary: this implementation relies on the host to authorize it.

The overall shape is suitable for a small structural cache. However, output-path handling permits writes outside the intended directory, cache contents can survive refresh without verification, and lint currently provides substantially less assurance than its name and status output suggest. The snapshot’s tests establish basic behavior, not complete OKF v0.2 conformance. Findings below are based on static inspection; tests were not executed.

## 2. Required fixes only

### 1. High — Output symlinks escape the write boundary

**File:** `lib/compile.mjs`

**Defect:** Only `.okf` itself is checked for being a symlink. Descendant directories and output files are followed by `mkdir`, `readFile`, and `writeFile`. For example, `.okf/files` can point to an external directory; compiling `src/auth.ts` then writes outside the repository. A symlink at `.okf/repository.md` can overwrite an external file. The lexical `inside()` check does not protect deletion through symlinked ancestors either.

**Smallest code change:** Centralize output-path validation and apply it before reads, writes, and deletions: reject symlinks in every existing component beneath `.okf`, validate the expected file type, and restrict deletion targets to generated concept paths. Use exclusive temporary files and atomic replacement for output files rather than following existing leaf paths. Reject a symlinked bundle root in the lint/status entry points as well.

**Regression test:** Pre-create `.okf/files` and `repository.md` as external symlinks; compilation must fail without modifying either external target.

### 2. High — Refresh trusts modified and injected concept content

**Files:** `lib/compile.mjs`, `lib/query.mjs`

**Defect:** A concept is considered unchanged when source hashes and edges match and its output path merely exists. Editing a generated concept therefore survives subsequent `query` refreshes. Moreover, `loadConcepts()` loads every non-reserved Markdown file with a `type`, including files never generated by this compiler.

A test can replace a generated body with arbitrary instructions or add `.okf/injected.md`; a normal query then returns that content as an “OKF slice.”

**Smallest code change:** Compare each existing concept with its expected deterministic rendering before keeping it. Restrict query loading to `repository.md` and concept paths in the freshly computed compilation inventory. For `refresh: false`, use an explicitly validated inventory rather than recursively trusting arbitrary Markdown.

### 3. Medium — Guide extraction violates the no-source-text contract

**Files:** `lib/compile.mjs`, `lib/query.mjs`, `lib/guidance.mjs`

**Defect:** `renderConcept()` copies the first eight nonempty guide lines, up to 400 characters. Thus README or AGENTS prose—including a secret or an instruction directed at the agent—is stored and returned verbatim despite the system prompt and query header saying the bundle contains no source text.

**Smallest code change:** Remove the `excerpt(file.text)` insertion and use structural guide metadata only. Add a short statement to the query header or system guidance that repository-derived names and metadata are untrusted data, not instructions.

**Regression test:** Put a unique prose marker in `README.md`; it must not appear in its generated concept or query output.

### 4. Medium — Lint accepts missing or invalid bundle scaffolding

**File:** `lib/lint.mjs`

**Defect:** An empty directory returns `ok: true`. Deleting the root index or log is not detected. A root index with `okf_version: "9.9"` also passes, as does an unterminated frontmatter block containing the substring `okf_version:`. Consequently, `lintOk` can report success for bundles that do not satisfy the compiler’s own advertised structure.

**Smallest code change:** Explicitly require the root `index.md`, `log.md`, and generated directory indexes. Parse the root frontmatter with a closing-delimiter requirement, require the version value to equal `"0.2"`, and reject `type` there. Validate that generated index links resolve to existing bundle entries.

**Regression tests:** Empty directory, missing root index, wrong version, unterminated frontmatter, and a dangling index link must each fail lint.

### 5. Medium — Deleted directories leave stale indexes and dangling links

**File:** `lib/compile.mjs`

**Defect:** `pruneEmpty()` runs before indexes are regenerated, but obsolete directories still contain their old `index.md`. Those directories never become empty, and `writeIndexes()` only updates currently needed directories. Removing the last source under `src/old/` leaves an index linking to its deleted concept.

**Smallest code change:** Compute the expected index-path set in `writeIndexes()`, delete generated indexes absent from that set, then run `pruneEmpty()` after index reconciliation.

**Regression test:** Compile `src/old/a.ts`, delete it, and compile again; neither its concept nor the obsolete `src/old/index.md` should remain.

### 6. Medium — Valid filenames produce broken Markdown links and source URIs

**Files:** `lib/compile.mjs`, `lib/text.mjs`

**Defect:** Link labels and destinations interpolate repository paths directly. A filename such as `a#b.ts` creates a link interpreted as a fragment rather than a filename; spaces, brackets, and parentheses also break generated Markdown. `sourceUri()` uses `encodeURI`, which leaves `#` and `?` as URI delimiters.

**Smallest code change:** Add separate helpers for Markdown-label escaping and path-segment encoding. Encode each path segment with `encodeURIComponent`, preserving only the separating `/`, and apply these helpers to overview, index, neighbor, and source-URI generation.

**Regression test:** Compile files containing spaces, `#`, `?`, and brackets; parsed links and decoded source URIs must resolve to the original filenames.

### 7. Medium — Rust module resolution can point to the wrong source

**File:** `lib/compile.mjs`

**Defect:** All Rust `mod child;` declarations resolve relative to the declaring file’s directory. For `src/foo.rs`, Rust normally looks under `src/foo/child.rs` or `src/foo/child/mod.rs`, not `src/child.rs`. If the latter exists, the compiler produces a false dependency. `pub mod child;` declarations are also omitted.

**Smallest code change:** Choose the module base according to the declaring filename: its directory for `lib.rs`, `main.rs`, and `mod.rs`; its extensionless path for ordinary module files. Allow optional Rust visibility in the declaration matcher. Skip declarations with an explicit `#[path]` override unless that override is handled.

**Regression test:** With both `src/child.rs` and `src/foo/child.rs` present, `src/foo.rs` must link only to the latter.

### 8. Medium — Empty compiled repositories are reported as uncompiled

**File:** `lib/status.mjs`

**Defect:** `compiled` is determined by whether state contains any indexed files. Compiling an empty repository—or one containing only ignored files—creates a bundle, but status still says no bundle exists and omits lint results.

**Smallest code change:** Determine compilation existence from a valid state file and bundle root index, not the number of indexed entries. Return normal status and lint fields with `indexedFiles: 0` for an empty compiled bundle.

**Regression test:** Status must change from `compiled: false` to `compiled: true` after compiling an empty directory.

### 9. Medium — State timestamps can remain stale after a successful refresh

**File:** `lib/compile.mjs`

**Defect:** `next` records current mtimes, but state is written only when concept content or the overview changes. Touching a non-newest source without changing its contents leaves `.state.json` stale. If the previously newest file is subsequently deleted before another compile, status reports an incorrect `newestSourceMtime` for the remaining indexed files.

**Smallest code change:** Persist state whenever its serialized contents differ, independently of concept-write and log-update counters. If concept provenance is intended to reflect current source mtime, include that timestamp in the concept reuse comparison too.

**Regression test:** Touch a non-newest file, compile, and assert its recorded state mtime equals the filesystem mtime.

### 10. Medium — Concurrent compilation can publish inconsistent or partial output

**File:** `lib/compile.mjs`

**Defect:** CLI processes and DSH calls can compile the same root concurrently. Each reads old state and then independently writes concepts, indexes, log, and state. A delayed older compilation can overwrite a newer compilation’s state or concepts. Direct `writeFile()` calls also expose truncated or partially written Markdown and JSON to another reader.

**Smallest code change:** Serialize compilation per canonical root with an exclusive filesystem lock, released in `finally`, and publish individual files using same-directory temporary files plus atomic rename. Keep query loading within the same synchronization boundary so another compilation cannot replace the bundle while it is being loaded.

**Regression test:** Pause one compilation after its scan, change a source, and start a second compilation. After both complete, state, concepts, and query output must consistently reflect the latest source, and no reader should observe partial JSON or Markdown.
